# Deterministic Agent Evaluation

---

## Evaluating System Decisions Instead of Only Generated Text

---

## 1. Abstract

LLM applications are often evaluated primarily by inspecting the text generated by the model.

For agentic systems, this is insufficient because the system must also make operational decisions such as selecting tools, executing API calls, following expected workflows, and handling failures.

This pattern introduces deterministic evaluation of agent behavior at the system level.

---

## 2. Evaluation Model

```text
     User Request
           ↓
Expected Tool / Workflow
           ↓
 Actual Agent Decision
           ↓
    Tool Execution
           ↓
    Execution Result
           ↓
Deterministic Evaluation
```
---

## 3. Evaluation Dimensions

The evaluation system can compare:

- expected tools;
- selected tools;
- actual execution path;
- execution outcome;
- API failures;
- fallback behavior;
- failure localization;
- final workflow state.

---

## 4. Core Principle

The probabilistic nature of LLM-generated text does not prevent deterministic evaluation of the surrounding software system.

The evaluator therefore focuses on observable system behavior rather than attempting to assign deterministic meaning to every generated sentence.

---

## 5. Failure Localization

Failures can be classified across different stages:

```text
   Tool Selection
          ↓
   Tool Execution
          ↓
   Data Retrieval
          ↓
   Data Processing
          ↓
Response Construction
```
This makes it possible to determine whether an incorrect result originated from reasoning, tool selection, execution, retrieval, processing, or response generation.

---

## 6. Engineering Objective

The objective is to make agentic systems testable as software systems rather than treating them as opaque conversational models.

---

## 7. Application

This approach was implemented for the NASA Enterprise Mission Control Agent using deterministic evaluation logic around the LangChain4j agent workflow.
